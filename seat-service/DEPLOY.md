# Deploying the church seat service

Nothing in here has been deployed and no accounts have been created. These are the steps Clayton runs.

## Why this stack
Cloudflare Workers + D1 (SQLite). The free tier covers 100k requests/day and 5 GB of D1, far more than we need: about 15 devices × a few calls/day per church. If the free-tier limits ever bite, Workers Paid is **$5/mo flat**. There are no servers to patch, TLS is automatic, and WebCrypto (Ed25519/ECDSA/RSA) is built in. The same code runs under plain Node for tests (`node --test`, no build step).
**Expected cost: $0/mo** (or $5/mo on Workers Paid). Domain optional (~$10/yr); the `*.workers.dev` URL works.

## Commands
```bash
cd seat-service && npm ci
npx wrangler login
npx wrangler d1 create tabernacle-tools-seats          # paste database_id into wrangler.toml
npx wrangler d1 migrations apply tabernacle-tools-seats --remote   # applies 0001_init + 0002_trial_history (v0.13) + 0003_cross_app (v0.18)
node scripts/keygen.ts                              # prints the 3 generated secrets + app public key
npx wrangler secret put ENTITLEMENT_SIGNING_KEY     # base64 PKCS8 Ed25519 private key from keygen
npx wrangler secret put SESSION_SECRET              # from keygen
npx wrangler secret put SUB_PEPPER                  # from keygen; NEVER rotate (it keys user lookup)
npx wrangler secret put ASC_ISSUER_ID
npx wrangler secret put ASC_KEY_ID
npx wrangler secret put ASC_PRIVATE_KEY < SubscriptionKey_XXXX.p8
npx wrangler deploy
```
Then in the app: put the keygen public key hex into `core/sync/SeatKeys.h` (`kSeatPublicKeyHex`) and the worker URL into `kSeatServiceUrl`, and build with `-DWR_STORE_BUILD=ON`.
For a staging (Sandbox) worker: `wrangler deploy --env staging`, with `APPSTORE_ENV=Sandbox` and its own D1 database.

## Secrets summary
`SESSION_SECRET`, `SUB_PEPPER`, `ENTITLEMENT_SIGNING_KEY` (generated by keygen) · `ASC_ISSUER_ID`, `ASC_KEY_ID`, `ASC_PRIVATE_KEY` (from App Store Connect). Plain vars in wrangler.toml: `BUNDLE_ID`, `SIWA_AUDIENCES`, `APPSTORE_ENV`.
If the signing key leaks: generate a new one, ship an app update with the new public key, and redeploy. Old tokens die within 30 days anyway.

## Verify after deploy
- `curl https://<worker>/healthz` → `{"ok":true}`
- App Store Connect → Notifications → **Request a Test Notification** → the worker log shows a `TEST` (it's ignored, returns 200)
- Sandbox tester: subscribe to Church → create team → invite → join on a second device.

## One free trial per person (v0.13)
- Migration `0002_trial_history.sql` adds `trial_history` (key_hash = HMAC(SUB_PEPPER, "trial-sub:" + Apple sub), otid_hash = SHA-256 of the
  original transaction id, first_trial_at, source), `users.trial_key`, and `teams.in_trial` / `teams.trial_blocked`.
  Existing deployments: run `npx wrangler d1 migrations apply tabernacle-tools-seats --remote` before deploying the new worker.
- Recorded when a leader creates a team on a trial transaction (offerType 1) and when a SUBSCRIBED/OFFER_REDEEMED notification carries a trial.
  A second trial for the same person: team creation answers 402 `trial_already_used`; a team that later reports one is flagged and gets
  no entitlement until the first paid renewal. Paid periods always work.
- **Privacy:** `trial_history` is NOT removed by `DELETE /v1/account` - otherwise deleting and re-creating the account would give a new
  trial. It contains only keyed hashes and a timestamp (no name, email, raw Apple id or transaction id) and can't be linked to a person
  without `SUB_PEPPER`. Say this in the Privacy Policy ("we keep a one-way fingerprint of your Apple sign-in to enforce one free trial").
- `SUB_PEPPER` must never rotate: it also keys trial_history.

## One subscription, every app (v0.18)
- Migration `0003_cross_app.sql` adds `purchases` (one row per App Store subscription, linked to the signed-in user, deleted with the account).
- `SIWA_AUDIENCES` in wrangler.toml lists all four bundle ids. The In-App Purchase key (secret `ASC_PRIVATE_KEY`) works for every app in the account; the Worker puts each app's bundle id in the Server API token.
- Cost: still the free Workers + D1 tiers (a few requests per user per day). No new services.
